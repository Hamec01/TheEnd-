## Быстрый маршрут правки квеста

1. Найти квест в админке `Quests`.
2. Проверить `category`, `status`, `kingdomId`, `npcId`, `startLocationId`, `targetLocationId`.
3. Проверить `Steps`, `Objectives`, `Conditions`, `Triggers`, `Rewards`.
4. Открыть `Dialogues` и проверить выдачу/блокировку старта/ветки `active/completed`.
5. Открыть `NPC` и проверить `dialogues` и `questBindings`.
6. Открыть `Zone Editor` и проверить `requiredQuestId`, `requiredQuestStatus`, `requiredStepId`, `requiredObjectiveId`, `hideAfter*`, `questLaunch`.
7. Если world map ведёт не туда, проверить `questLaunch.action = start_quest_battle` и порядок обработки в runtime.
8. После контент-правки прогнать typecheck и тесты.

## Важное правило про кириллицу

- Русский текст в JSON нельзя править через shell-скрипты, если есть риск перекодировки.
- Для ручных правок текста безопаснее использовать прямой patch.
- Если в игре появились `?????`, сначала искать испорченные строки в `theend_content.local.json`, а не в UI.
- Если читаешь `.md` или `.json` через PowerShell для проверки, лучше явно указывать `Get-Content -Encoding UTF8`, иначе можно принять неверное отображение в консоли за реальную поломку файла.

## Живые проблемы и решения

Этот раздел нужно пополнять по мере работы.

### 1. В игре появились `?????` вместо русского текста

- Симптом:
  - диалоги и названия в игре показываются как `?????`
- Где нашли:
  - [apps/backend/data/theend_content.local.json](C:/theend/apps/backend/data/theend_content.local.json)
- Причина:
  - кириллица была испорчена при записи через shell/PowerShell-путь
- Решение:
  - чинить строки напрямую patch-редактированием
  - не править русский JSON через shell-скрипты, если есть риск перекодировки

### 2. В Phaser-бою карта и клики не совпадают с сеткой из админки

- Симптом:
  - в `Battle Maps` блоки и проходы выглядят в одном месте
  - в самом бою Phaser показывает тот же фон, но клик попадает в другую клетку
  - battlefield сжимается в узкий прямоугольник или квадрат по центру, а вокруг остаются чёрные поля
  - создаётся ощущение, что игровая сетка “съехала” относительно battle map
- Где нашли:
  - [apps/frontend/src/battle/renderers/PhaserBattleRenderer.tsx](C:/theend/apps/frontend/src/battle/renderers/PhaserBattleRenderer.tsx)
- Причина:
  - Phaser держал внутренний canvas выше реального host: `360px` даже когда DOM-область боя была ниже
  - viewport считался от базовых `12x12`, поэтому широкий battlefield на wide-host сжимался в маленький центрированный кусок
  - из-за этого фон, viewport и координаты мыши жили в разных масштабах
- Решение:
  - внутренний размер Phaser canvas должен совпадать с реальным размером host
  - viewport должен подстраиваться под aspect ratio host, а не оставаться маленьким квадратом посередине
  - клиповать Phaser camera ровно в реальный viewport
  - вычитать `viewportOriginX/Y` при резолве клика в клетку
  - игнорировать клики вне активного viewport, даже если они попали в большой host canvas
  - после правки обязательно руками проверить:
    - выбор врага левым кликом
    - открытие cell-context-menu правым кликом
    - движение через cell action без смещения на соседнюю клетку

### 2. Квест есть в админке, но NPC не выдаёт его корректно

- Симптом:
  - `Поле павших` есть в `Quests`, но король не работал как нормальный квестодатель
- Где нашли:
  - `questBindings` у `npc_argos_king_gramar_fireblade`
  - [apps/frontend/src/services/npcAdminNormalization.ts](C:/theend/apps/frontend/src/services/npcAdminNormalization.ts)
- Причина:
  - в локальном контенте использовалась legacy-роль `quest_giver`, а runtime ожидал `giver`
- Решение:
  - в контенте заменить `quest_giver` на `giver`
  - в runtime добавить нормализацию alias-роли `quest_giver -> giver`

### 3. Король показывает ноду про `Поле павших`, но скрывает кнопку старта

- Симптом:
  - после завершения `Кто я?` у короля видна только кнопка `Мне нужно подготовиться.`
- Где нашли:
  - [apps/frontend/src/services/questRuntime.ts](C:/theend/apps/frontend/src/services/questRuntime.ts)
- Причина:
  - `canStartQuest(...)` проверял только `player.completedQuestIds` из runtime-player
  - сохранённый completed state уже был в local quest state, но не попадал в текущий объект игрока
- Решение:
  - `quest_completed` и `quest_active` должны уметь смотреть в реальные сохранённые `PlayerQuestState`
  - не полагаться только на поля текущего runtime-player

### 4. Warning `target zone not found for objective` для battle objective

- Симптом:
  - в консоли:
    - `target zone not found for objective`
    - `targetId: battlemap_argos_artalon`
- Где нашли:
  - [apps/frontend/src/worldmap/WorldMapScreen.tsx](C:/theend/apps/frontend/src/worldmap/WorldMapScreen.tsx)
- Причина:
  - auto-marker логика пыталась искать `battlemap_*` как обычную world zone
  - это неверно для `battle_objective`
- Решение:
  - для `battle_objective` не использовать `battleMapId` как обычный zone target
  - marker target для battle objective должен идти только через world zone, если она реально есть

### 5. Зона `Поле павших` видна, но бой не стартует

- Симптом:
  - игрок стоит в зоне
  - квест активен
  - битва не запускается
- Где нашли:
  - [apps/frontend/src/worldmap/WorldMapScreen.tsx](C:/theend/apps/frontend/src/worldmap/WorldMapScreen.tsx)
- Причина:
  - `questLaunch` был настроен на `triggerOn: enter`
  - если автозапуск на входе уже был пропущен, `Осмотреться` не пыталось стартовать `start_quest_battle`
- Решение:
  - inspect-path должен уметь пробовать `questLaunch`
  - это хороший recovery, если входной автозапуск не сработал вовремя

### 6. `api/combat/start` отвечает `400 Bad Request` на quest battle

- Симптом:
  - битва доходит до backend, но сервер отвечает `400`
- Где нашли:
  - [apps/backend/src/combat/dto.start-combat.dto.ts](C:/theend/apps/backend/src/combat/dto.start-combat.dto.ts)
  - battle map `battlemap_argos_artalon`
- Причина:
  - backend DTO отставал от текущей battle map domain-модели
  - не принимались поля:
    - `objectives[].failOnAllSourceActorsDead`
    - `scriptEvents[].questEffect`
- Решение:
  - расширить server DTO под актуальную battle map schema
  - при 400 на `combat/start` всегда сравнивать:
    - frontend battle map payload
    - backend DTO
    - `packages/rpg-domain` model

### 7. Что проверять, если quest battle не стартует

1. Квест реально active у персонажа.
2. Current step совпадает с `questLaunch.questStepId`.
3. `questLaunch.questObjectiveId` совпадает с objective в текущем step.
4. `battleMapId` существует.
5. `battleObjectiveIds` существуют внутри battle map.
6. `triggerOn` совпадает с реальным путём запуска: `enter`, `interact` или `inspect`.
7. Backend DTO умеет принять все поля карты.

### 8. Quest battle starts, but movement does not work

- Symptom:
  - battle opens
  - `wait/skip turn` still works
  - movement in battle is unreliable or unavailable
- Where found:
  - [apps/frontend/src/battle/renderers/PhaserBattleRenderer.tsx](C:/theend/apps/frontend/src/battle/renderers/PhaserBattleRenderer.tsx)
- Cause:
  - combat API and battle content are valid
  - the failure is in the Phaser battle interaction path, not in quest launch logic
  - most often it is not the quest battle itself, but a mismatch between:
    - host DOM size
    - internal Phaser canvas size
    - rendered viewport width/height
- Resolution:
  - first verify movement through the battlefield cell context menu
  - if context-menu movement works, the backend and battle content are fine, and the bug is in click-to-cell resolution
  - check:
    - `setHostSize(...)`
    - viewport aspect adaptation
    - `viewportOriginX/Y`
    - CSS-stretch of `.phaser-battle-host canvas`

### 10. Battle map `scriptEvents` могут быть заполнены в админке, но реально не работать в бою

- Симптом:
  - в battle map есть `battle_start`, `objective_progress`, `objective_completed`
  - в UI редактора они выглядят настроенными
  - в рантайме бой идёт, но сообщения/questEffect не происходят
- Где нашли:
  - [apps/backend/data/theend_content.local.json](C:/theend/apps/backend/data/theend_content.local.json)
  - [apps/backend/src/combat/dto.start-combat.dto.ts](C:/theend/apps/backend/src/combat/dto.start-combat.dto.ts)
  - [apps/backend/src/combat/combat.service.ts](C:/theend/apps/backend/src/combat/combat.service.ts)
- Причина:
  - DTO уже принимал `scriptEvents`
  - но backend battle runtime почти не исполнял их после старта боя
  - из-за этого `scriptEvents` были больше схемой данных, чем реальным поведением
- Решение:
  - при старте боя запускать `battle_start`
  - при прогрессе objective запускать `objective_progress`
  - при завершении objective запускать `objective_completed`
  - `once` нужно уважать через список уже сработавших event id
  - `questEffect.complete_objective` надо дедупить с обычным objective-completion pipeline, чтобы не завершать цель дважды

### 11. У battle NPC может быть `equipment = null`, но это не всегда значит «без оружия»

- Симптом:
  - в JSON у боевых NPC в карте поле `equipment` пустое
  - визуально кажется, что солдаты и лучники вообще без оружия
- Где нашли:
  - [apps/backend/src/combat/combat.service.ts](C:/theend/apps/backend/src/combat/combat.service.ts)
- Причина:
  - backend подставляет fallback-экипировку по `combatRole`, если в карте не задано явное оружие
  - для melee/ranged/mage берутся дефолтные наборы оружия и брони
  - проблема была не только в оружии, а ещё и в том, что статы NPC были слишком однообразны
- Решение:
  - если `equipment` пустое, backend всё равно должен давать роль-зависимое оружие
  - дополнительно полезно делать детерминированный разброс статов от игрока до `±30%`
  - профиль статов должен зависеть от роли:
    - melee -> сила/телосложение/выносливость
    - ranged -> ловкость/восприятие
    - mage -> интеллект/воля/мана
### 12. Battle `scriptEvents` have two runtime layers

- Symptom:
  - a battle map event exists in admin data
  - backend may already trigger it
  - but the player still does not clearly see the line or pause in the battle UI
- Where found:
  - [apps/backend/src/combat/combat.service.ts](C:/theend/apps/backend/src/combat/combat.service.ts)
  - [apps/frontend/src/battle/BattlePanel.tsx](C:/theend/apps/frontend/src/battle/BattlePanel.tsx)
- Cause:
  - layer 1 is backend trigger execution
  - layer 2 is frontend playback and log handling of `effect_triggered`
  - if layer 2 is missing, the event is technically real but feels invisible
- Resolution:
  - keep backend emission for `battle_start`, `objective_progress`, `objective_completed`
  - frontend should explicitly handle `effect_triggered`
  - if `pauseCombat = true`, playback should give the message a longer readable pause
