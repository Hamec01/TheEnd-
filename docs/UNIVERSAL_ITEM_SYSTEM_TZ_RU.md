# ТЗ: универсальная система эффектов предметов

## Цель

Развивать слой `effects / augments / sockets / blacksmith / item sets` поэтапно, без разрушения старых контрактов предметов, контента и runtime-поведения.

## Обязательные ограничения

- Не удалять и не переименовывать legacy-поля: `bonuses`, `damageMin`, `damageMax`, `armorValue`, `effects`, `combatEffects`, `useEffect`.
- Все новые поля должны оставаться опциональными.
- Старые JSON-бэкапы и импорт контента должны продолжать загружаться без ручной миграции.
- Боевой runtime и логика старых consumable/use-эффектов не должны ломаться ради нового item-layer.

## Актуальное состояние на 2026-06-01

Сделано:

- Контракты новых сущностей и полей в `apps/backend/src/content/content.types.ts`.
- Нормализация, импорт/экспорт и integrity-checks в `apps/backend/src/content/content.service.ts`.
- Серверный резолвер экипировки, аугментов, сетов и пассивных стат-бонусов в `apps/backend/src/content/item-effects.resolver.ts`.
- Базовый preview-слой для админки.

Уточнение:

- Старый `docs/COPILOT_TZ_HANDOFF.md` уже частично устарел: `item-effects.resolver` фактически внедрён и покрыт тестами.

## Этапы внедрения

### Этап 1. Безопасный presentation-layer

Цель: довести до консистентности отображение новых систем в админке и preview без изменения боевого расчёта.

Задачи:

- Привести `admin-preview.builder` к тем же правилам валидации, что и resolver.
- Корректно показывать неактивные аугменты: несовместимый тип, отсутствующий augment payload, mismatch activation contexts.
- Расширять тесты только вокруг preview/builders.

### Этап 2. Formatter и UX описаний

Цель: стабильно формировать человекочитаемые описания для item effects, set bonuses и augment effects.

Задачи:

- Держать единый formatter-слой для item/set/augment preview.
- Не менять структуру данных ради UI.
- Добавлять тесты на совместимость старых и новых типов эффектов.

### Этап 3. Blacksmith runtime

Цель: безопасно включить операции кузнеца поверх instance-state предмета.

Задачи:

- Разблокировка слотов.
- Добавление blacksmith-сокетов.
- Применение `slotUpgradeRules` с failure modes.
- Явное отделение template item от character item instance.

### Этап 4. Item sets в gameplay/UI

Цель: вывести активные бонусы сетов в клиент и использовать их без дублирования логики.

Задачи:

- Отдать в API активные set bonuses и их источники.
- Показать прогресс по pieces и активированные пороги.
- Не считать предметы из инвентаря, только экипированные.

## Первый спринт внедрения

В этой итерации начинаем с самого безопасного слоя:

1. Актуализируем ТЗ.
2. Синхронизируем preview сокетов с resolver-правилами.
3. Закрываем изменения тестами.

## Следующие рекомендуемые задачи

- Вынести общие helper-правила для activation contexts, чтобы preview и resolver не расходились.
- После этого переходить к blacksmith instance-операциям, не затрагивая legacy item usage.
