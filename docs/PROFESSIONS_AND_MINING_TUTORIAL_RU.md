# THE END: Туториал по профессиям и Горняку

Этот гайд объясняет:
- что такое профессия в проекте;
- как настроить Горняка (шахты, глубины, блоки, опасности, добычу);
- как привязать вход в миниигру к локации через NPC-диалог;
- как проверить, что цикл работает от входа до финализации результата.

## 1. Как это устроено в проекте

Профессии состоят из 4 слоев:
1. Модель персонажа: уровень, XP, очки навыков, изученные навыки, выбранные ветки.
2. Админ-контент: навыки, ветки, данные миниигры (для Горняка: шахты/глубины/таблицы).
3. Runtime: запуск миниигры, расчеты, лут, риски, финализация.
4. UI игрока: панель профессий, экран миниигры, результат.

- Модель профессий домена: apps/backend/../packages/rpg-domain/src/professions.ts

## 3. Что и для чего в Горняке

Сущности Горняка:
1. Mine (Шахта): общая карточка шахты, требования по уровню, тема и список глубин.
2. Depth (Глубина): размеры сетки, лимиты ударов, риск, ссылки на таблицы.
3. Block table (Блоки): какие типы блоков появляются и с каким весом.
4. Hazard + Hazard table (Опасности): типы угроз и их распределение по глубинам.
5. Loot table (Добыча): предметы и диапазоны количества.
6. Skill tree (Навыки/ветки): модификаторы эффективности, выживания и маршрута.

## 4. Пошагово: создать профессию -> локацию -> миниигру

### Шаг 1. Создать/настроить профессию

1. Откройте админку Профессии.
2. Выберите профессию (для миниигры уже реализован Горняк).
3. Во вкладке Навыки добавьте узлы:
- id, name, description;
- requiredLevel;
- skillPointCost;
- requiredSkillIds;
- branchId (если это узел ветки);
- effects (тип, value, chance, condition, params).
4. Во вкладке Ветки добавьте ветки и группы исключения:
- exclusiveGroupId обязателен для взаимоисключающих выборов;
- requiredSkillIds для переходных ворот.

### Шаг 2. Создать данные миниигры Горняка

Во вкладках Горняка (Шахты/Глубины/Блоки/Опасности/Добыча):

1. Шахты:
- создайте mine id, name, requiredMiningLevel;
- перечислите depthIds.

2. Глубины:
- создайте depth id + mineId;
- задайте rows/columns/baseHits/staminaCostPerHit/risk;
- укажите blockTableId/hazardTableId/lootTableId.

3. Блоки:
- создайте table id;
- добавьте entries с type и weight;
- для entries задайте payload-логику:
  - loot_item
  - loot_material
  - rune_trace
  - hazard_ref
  - event_ref
  - gold (goldMin/goldMax)
- passage используется для спуска;
- exit считается legacy и не нужен для выхода.

4. Опасности:
- создайте hazard entries (урон, стамина, потери добычи, тип);
- соберите hazard table (веса + depth range).

5. Добыча:
- создайте loot table (itemId, вес, min/max quantity, depth/rarity).

### Шаг 3. Сделать точку входа из локации

Рекомендуемый путь входа: через NPC-диалог в нужной локации.

1. Разместите NPC в нужной зоне/локации.
2. В Диалогах добавьте choice с действием open_mine.
3. Укажите mineId вашей шахты.
4. В рантайме intent OPEN_MINE откроет MiningScreen.

Важно: для Горняка не требуется отдельный тип локации шахты. Вход можно делать через обычный interaction flow (NPC/диалог).

### Шаг 4. Проверить полный цикл миниигры

Ожидаемое поведение:
1. Удар по блоку добавляет добычу только во временную сумку забега.
2. Реальный инвентарь не меняется до конца забега.
3. Кнопка Выйти из шахты доступна всегда (при active run).
4. После завершения всегда показывается экран результата.
5. Только после подтверждения результата происходит перенос:
- savedLoot -> инвентарь;
- savedGold -> золото;
- XP -> профессия.

## 5. Пошагово: создать новую профессию с миниигрой (общий шаблон)

Если вы делаете не Горняка, а новую профессию с собственной миниигрой:

1. Домен:
- добавьте definition в packages/rpg-domain/src/professions.ts.

2. Админка:
- добавьте вкладки профессии в PROFESSION_SPECIFIC_TABS (ProfessionEditorTabs.tsx);
- создайте редакторы контента в apps/frontend/src/admin/<your-profession>/.

3. Repository слой:
- сделайте load/save/find для сущностей миниигры (по аналогии с miningRepository.ts).

4. Runtime слой:
- отдельный runtime service миниигры (по аналогии с miningRuntime.ts);
- четко разделите temporary state и finalize state.

5. UI:
- экран миниигры + экран результата;
- кнопка финализации результата, которая и делает реальный трансфер наград.

6. Интеграция карты/диалогов:
- intent в dialogueRuntime;
- обработчик в WorldMapScreen.

7. Валидация:
- предупреждения в админке о разрывах ссылок и нелогичных payload.

## 6. Минимальный чеклист перед релизом

1. Typecheck без ошибок.
2. Тесты зеленые.
3. Вход в миниигру из диалога работает.
4. Временная сумка не пишет в реальный инвентарь во время run.
5. Итоговый экран появляется всегда.
6. Финализация переносит только saved-награды.
7. Ветки действительно взаимоисключающие.
8. Нераспознанные itemId/hazardId не роняют runtime.

## 7. Частые ошибки

1. Добыча уходит сразу в инвентарь при ударе.
- Исправление: переносить только при подтверждении результата.

2. Нет exclusiveGroupId у choice-веток.
- Итог: можно взять обе стороны дерева.

3. skill effect ссылается на несуществующие hazard/block payload.
- Исправление: добавить валидаторы связности.

4. Используется exit блок как обязательный выход.
- В актуальной логике safe exit не зависит от exit блока.

## 8. Быстрый сценарий smoke-test (Горняк)

1. Откройте диалог NPC -> open_mine.
2. Разбейте несколько блоков, убедитесь что растет временная сумка.
3. Проверьте, что обычный инвентарь игрока не изменился.
4. Нажмите Выйти из шахты.
5. На экране результата проверьте:
- статус,
- добыто/сохранено/потеряно,
- золото,
- XP.
6. Нажмите Подтвердить результат.
7. Проверьте, что только теперь обновились инвентарь, золото и уровень Горняка.
